# Excel → Markdown 仕様書生成スキル

## 前提条件

```bash
pip3 install openpyxl oletools
```

スキル実行時にインストール済みか確認し、未インストールなら自動インストールする。

## ディレクトリ規約

このスキルはプロジェクトルート内の以下の構成を前提とする:

```
<project_root>/
├── xlms/    ← Excel ファイル（.xlsx/.xlsm）の格納場所
└── docs/    ← 生成した MD 仕様書の出力先
```

- 対象ファイルが `xlms/` にない場合は `xlms/` にコピーしてから処理する
- MD 仕様書は常に `docs/<元ファイル名（拡張子除く）>_仕様書.md` に出力する

---

## 実行手順

### Step 1: ファイルとプロジェクトルートを特定

1. 対象 Excel ファイルのパスを確認する
2. プロジェクトルートを特定する（`xlms/` と `docs/` が存在するディレクトリ）
3. ファイルが `xlms/` 以外にある場合は `xlms/` にコピーする
4. 拡張子で処理を分岐:
   - `.xlsx` → VBA抽出ステップ（Step 3〜3.5）をスキップ
   - `.xlsm` / `.xlsb` → 全ステップ実行

### Step 2: セル・構造解析スクリプト実行

```bash
python3 .cursor/skills/excel-to-md/scripts/extract_excel.py "<xlms/ファイルパス>"
```

スクリプトが以下のJSON構造を標準出力する:
- `sheets`: シート一覧（名前・行数・列数・visible状態）
- `cells`: 全セルの値（data_only=True）
- `formulas`: 全数式（data_only=False）
- `merged_cells`: マージセル範囲
- `defined_names`: 名前付き範囲
- `buttons`: ボタン・マクロ割り当て
- `external_links`: 外部ファイル参照

### Step 3: VBA 抽出（.xlsm のみ）

```bash
olevba "<xlms/ファイルパス>" 2>&1
```

出力からモジュール単位でVBAコードを分離・整理する。
以下の情報を各モジュールから抽出する:
- **モジュール名・種別**（.bas / .cls / .frm）
- **プロシージャ名・種別**（Sub / Function / Property / Event）
- **DB接続文字列・SQL文**
- **CommandBar ボタン定義**（Caption / OnAction / FaceId）
- **シートの Visible 制御コード**（`xlSheetHidden` / `.Visible = True/False`）

### Step 3.5: フォーム解析（.xlsm のみ）

OLE ストリームからユーザーフォームのコントロール情報を抽出する:

```python
import zipfile, olefile, io, re

z = zipfile.ZipFile("<xlms/ファイルパス>")
data = z.read('xl/vbaProject.bin')
ole = olefile.OleFileIO(io.BytesIO(data))

# フォーム名の一覧取得
entries = ole.listdir(streams=True, storages=True)
frm_names = set(e[0] for e in entries if len(e) >= 2 and re.match(r'^i\d+$', e[1]))

# 各フォームのコントロール数カウント
for frm in frm_names:
    controls = [e for e in entries if e[0] == frm and len(e) == 2 and re.match(r'^i\d+$', e[1])]
    print(f"{frm}: {len(controls)} controls")

# コントロール名の抽出（バイナリ 'f' ストリームから）
form_data = ole.openstream([frm, 'f']).read()
names = re.findall(rb'[\x20-\x7e]{3,}', form_data)
```

コントロール名が取得できない場合は、VBA コード内の `Me.ControlName` / `FrmName.ControlName` の参照パターンから推定する。

### Step 4: MD仕様書の構成

[reference.md](reference.md) のテンプレートに従い、以下の10章構成で生成する:

1. **ファイル構成**
   - 1.1 シート一覧: 全シートを `✓/シート名/最大行/最大列/保存時Visible/VBAによる動的切替` の6列で列挙
   - 1.2 ユーザーフォーム一覧: 全 frm を `✓/フォーム名/コントロール数/主用途` で列挙
   - 1.3 VBA モジュール一覧: 全モジュールを `✓/モジュール/種別/プロシージャ数/主な役割` で列挙（**「主要」限定ではなく全件**）

2. **シート詳細**
   - 2.0 シート可視性一覧: VBA による非表示制御を一覧化（表示/非表示タイミング・制御プロシージャ）
   - 各シートに「非表示行・列」セクションを設ける（存在しない場合は「なし。」）
   - レイアウト構造は行範囲の説明 + `✓/セル/名前付き範囲/種別/実態/業務的意味` の6列テーブル
   - 種別は「VBA代入」「数式」「手動設定」「設定値」「DB読込」のいずれかを明記
   - セルの業務的意味は名前付き範囲の直訳ではなく業務上の意味を記載する

3. **名前付き範囲一覧**
   - 全件を `✓/名前/参照先/業務的意味` で列挙

4. **数式一覧**
   - シート別の件数サマリ + シートごとに `セル/数式/説明` のテーブル

5. **ボタン・マクロ対応**
   - 5.1 シート上のボタン（Form Control）
   - 5.2 ユーザーフォーム上のボタン（フォーム名・コントロール・キャプション・イベント・呼び出しプロシージャ・動作概要）
     全フォームのボタンを漏れなく列挙する。7章のイベント一覧と突き合わせ、5.2 に漏れがないことを検証する
   - 5.3 CommandBar に動的追加されるボタン（追加元・タイミング・Caption/OnAction/FaceId）

6. **VBA モジュール仕様**
   - 6.0 全プロシージャ一覧: `✓/モジュール/プロシージャ/種別/概要` で全件列挙（**「主要」限定ではなく全件**）
   - シェープ表示非表示系モジュールなど10件超を「（N件）」とまとめず、1行ずつ列挙する

7. **ユーザーフォーム仕様**
   - 各フォームのコントロール一覧: `✓/コントロール/種別/キャプション/親フレーム/用途`
   - コントロールが多い場合は「コントロール種別サマリ」（種別×件数）を先に示す
   - イベント一覧: `✓/イベント/動作概要`（DB操作・呼出しプロシージャを明記）

8. **DB 接続・外部連携**
   - 8.1 ODBC接続設定
   - 8.2 テーブル一覧: `✓/テーブル名/区分/主な用途/キー列/参照・更新列`（区分は「参照」「参照＋更新」「更新（DELETE+INSERT）」）
   - 8.3 主要 SQL（抜粋）
   - 8.4 外部ファイル連携: `ファイル / パス / ファイル名 / 処理 / 備考` の5列テーブル＋各ファイルの詳細サブセクションで構成
     - VBA ソースからパス文字列とファイル名生成ロジックを抽出する
     - 動的生成されるファイル名は生成パターンを明記する（例: yyyyMMdd.txt）
     - 各ファイルの詳細サブセクションに記載: 出力元プロシージャ・モジュール / パス生成ロジック（VBA引用）/ 出力例 / 記録・読込内容 / 削除・作成ロジック
     - 無効機能のファイルも同等の詳細度で記載し「（無効機能）」と明記する

9. **データフロー**
   - フロー名ごとにテーブル（起点/処理/結果）＋ツリー図（補助）の**2段構成**
   - テーブル・ツリー図の各行/ノードに場所マーク（📊🖥️🗄️📄）を付与
   - 最低限以下のフローを記述する:
     - 起動フロー
     - データ表示フロー
     - 更新フロー（DB更新がある場合）
     - モード別フロー（複数の主要動作モードがある場合）

10. **セキュリティ注意事項**
    - olevba 警告（AutoExec / Suspicious / IOC）を種別・キーワード・内容の3列で列挙

### Step 5: 出力

```
docs/<元ファイル名（拡張子除く）>_仕様書.md
```

に生成した MD を保存する。`docs/` が存在しない場合は作成する。

## スコープ外

以下は完全な再現が困難なため、明示的にスコープ外とする:
- セル書式（色・罫線・フォントサイズ）
- 条件付き書式
- グラフ・画像
- 印刷設定

必要な場合はスクリーンショットで補完する旨を記載する。

## 表記ルール（出力する MD に適用）

| 種別 | 表記 | 例 |
|---|---|---|
| モジュール（.bas / .cls） | **太字** | **スタート処理.bas** |
| ユーザーフォーム（.frm） | **太字** | **SoutiSenntaku.frm** |
| プロシージャ / イベント | `コード体()` | `生産情報開始処理()` ※Markdown制約上、斜体ではなくコード体で統一 |
| シート名 | 「」 | 「未処理品一覧」 |
| セル参照 | `コード体` | `$W$3` |
| 名前付き範囲 | `コード体` | `Amari` |
| DB テーブル / カラム | `コード体` | `ExKeikakuX` / `kakunin` |
| ユーザー操作 | （操作名） | （処理方法実行 Click） |
| 主要マーク | ✓ | ✓ = 保守時に最初に確認すべき項目 |

### データフロー 場所マーク

データフロー（9章）の各行・各ノードに付与する:

| アイコン | 種別 | 意味 |
|---|---|---|
| 📊 | シート操作 | ワークシート上のセル書込み・読取り・表示変更 |
| 🖥️ | 画面操作 | ユーザーフォーム（.frm）の表示・入力・操作 |
| 🗄️ | DB操作 | DB への SELECT / INSERT / UPDATE / DELETE |
| 📄 | VBA内部処理 | 変数計算・条件分岐など、画面・シートに直接関与しない処理 |

## 判断基準

- セルに値がない行は省略してよい
- VBAコードは処理フローの日本語解説を優先し、コード全文は掲載しない
- SQL文が含まれる場合はテーブル一覧・カラム説明を別セクションで整理
- 数式に科学的・業務的意味がある場合（半減期計算など）はコメントで補足
- 目次は各仕様書にデフォルトで含める。複数ファイルの仕様書を一括生成する場合、
  ユーザーが「ファイル一覧＋目次を別途用意する」と指定した場合は各仕様書の目次を省略してよい
- **「主要○○」という表現は使わない。全件を列挙し、✓ マークで主要度を示す**
- **各テーブルには必ず ✓ 列を設ける（章の凡例に従って判定）**
- **データフローは必ずテーブル＋ツリー図の2段構成で記述する**
- **データフローの各行・各ノードには場所マーク（📊🖥️🗄️📄）を付与する**
- 仕様書タイトルと `<ファイル名>` には xlsm/xlsx 拡張子を除いた名称を使用する
- 対象ファイル行には拡張子付きフルファイル名を記載する（例: Ex生産情報一覧1.xlsm）
- 類似名称のファイルが存在しうるため、ファイル名末尾の番号等を省略しない
- セルの業務的意味欄は名前付き範囲の直訳ではなく、VBAコードでの用途を読み取って記載する
- フォームのコントロール一覧では、コントロール数が10件を超える場合は種別サマリを先頭に置く
- CommandBar ボタンは動的登録のため VBA コードから Caption / OnAction / FaceId を抽出して記載する
- 仕様書は既存システムの保守ドキュメントとして記述する。
  技術移行（TypeScript 実装、Web 再構築など）の観点・推奨は含めない
- 8.2 テーブル一覧の「区分」は、VBA ソース内の SQL 文（SELECT / INSERT / UPDATE / DELETE）を
  全件走査して判定する。テーブル名の出現だけで判断しない
- ✓ マークは UPDATE / INSERT / DELETE の SQL が実際に存在するテーブルにのみ付与する。
  参照（SELECT）のみのテーブルには ✓ を付けない
- 更新テーブルの「参照/更新列」には、更新元のフォーム・プロシージャと更新条件を明記する
  例: 更新: `kshika`（SyoriSettei.frm から登録='1'/削除='0' に UPDATE）
