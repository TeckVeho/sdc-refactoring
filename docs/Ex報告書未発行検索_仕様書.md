### データフロー 場所マーク（9章）

9章のデータフロー（テーブル・ツリー図）では、処理が行われる場所を以下のアイコンで区別します。

| アイコン | 種別 | 意味 |
|---|---|---|
| 📊 | シート操作 | ワークシート上のセル書込み・読取り・表示変更 |
| 🖥️ | 画面操作 | ユーザーフォーム（.frm）の表示・入力・操作 |
| 🗄️ | DB操作 | Oracle DB への SELECT / INSERT / UPDATE / DELETE |
| 📄 | VBA内部処理 | 変数計算・条件分岐など、画面・シートに直接関与しない処理 |

### ✓（主要マーク）の判定基準

✓ は **保守時に最初に確認すべき項目** を示します。
判定基準は対象の種類ごとに以下のとおりです。

| 章 | 対象 | ✓ の判定基準 |
|---|---|---|
| 1.1 | シート | ユーザーが直接操作する、または VBA が動的に表示/非表示を切り替える |
| 1.2 | ユーザーフォーム | ユーザー入力を受け付ける、または業務フローの起点となる |
| 1.3 / 6.0 | VBA モジュール | ① ユーザー操作の起点 ② DB I/O を含む ③ 他モジュールから呼び出される ④ コード行数上位 25%　のいずれか |

| 3 | 名前付き範囲 | VBA から `Range()` で代入または参照され、業務ロジックに直結する |

### 6.5 **データ表示_変更登録**

モジュールレベル変数：

| 変数 | 型 | 用途 |
|------|----|------|
| `mmSQL` | String | SQL文バッファ |
| `mmRecC` | Single | レコード件数 |
| `mmFildC` | Single | フィールド数 |
| `mmSele` | String | SELECT句 |
| `mmFrom` | String | FROM句 |
| `mmWher` | String | WHERE句 |
| `mmROW` | Single | 処理行カウンタ |

#### `報告書データ表示()`
検索ボタンの起点。受付番号バリデーション → 一覧クリア → `データ読込()` → `最終完了日()` → `Sort()` → `高さ自動調整()` → `オートフィルタ設定()` → `印刷範囲設定()`

#### `データ読込()`
4パターンのSQLを UNION ALL で結合し `Disp_Sheet()` でシート書出：
1. 在庫データ（報告未発行）：`zaiko` + `sehmst` + `ExKeikakuX` + `ExSeihinJ`
2. 履歴データ（報告未発行）：`rich.zaikor@ricdb` + `sehmst` + `ExKeikakuX` + `ExSeihinJ`
3. 在庫データ（報告発行済Fax未送信）：同上
4. 履歴データ（報告発行済Fax未送信）：同上

動的条件：`SQLHyouji`（表示設定SQL）、`SQLfax`（Fax条件SQL）、`KaisyaCD`（会社コード）、`SyukkaDay`（出荷日）

#### `Fax送信()`
一覧の各行について報告書発行種別を確認し、Fax列が空の場合に初期値を設定：
- 種別に"Fax"を含む → "未"
- 含まない/"" → "不"

#### `最終完了日()`
4テーブル（`syouj1`, `rich.syoujr1@ricdb`, `syouj2`, `rich.syoujr2@ricdb`）から受付番号ごとの最大完了日を取得し、`JissekiTB`（W:X列）に格納。`KanDateC` の数式をコピー→値化して M列に最終完了日を設定。

#### `変更登録()`
1. 報告書発行フラグ=1のデータに表示設定「非」を自動付与（ユーザー確認あり）
2. `UmuSiki`・`RotSiki` の計算式をコピー→値化して変更有無を確定
3. Fax/表示設定変更（`HenkouSu` > 0）→ `ExKeikakuX` に `SQL_INSERT_UPDATE()`
4. ロット番号変更（`HenkouSuRot` > 0）→ `zaiko` or `rich.zaikor@ricdb` に `SQL_INSERT_UPDATE()`

#### `未登録検出在庫変更登録()`
起動時に実行。ExKeikakuXに未登録の受付番号、または在庫マスタと会社/製品コードが不一致のデータを検出し、`ExSeihinJ` + `sehmst` から報告書発行情報を取得して `ExKeikakuX` に INSERT/UPDATE。

## 10. セキュリティ注意事項

| # | 区分 | 内容 | リスク |
|---|------|------|--------|
| 1 | 認証情報 | DSN接続文字列にUID/PWDがハードコード（`ric`/`t6101`） | 高：ソースコード閲覧で資格情報が漏洩 |
| 2 | SQLインジェクション | セル値（`KaisyaCD`, `Uno`, `SyukkaDay`）を文字列結合でSQL構築 | 中：悪意あるセル入力でSQL注入の可能性 |
| 3 | トランザクション制御 | `SQL_INSERT_UPDATE()` は1件ずつCommit（ループ中にエラーで部分更新） | 中：データ不整合リスク |
| 4 | エラーハンドリング | `On Error Resume Next` 多用で異常検知が困難 | 中：サイレント障害 |
| 5 | シート保護 | 起動時にUnprotect後、再保護なし | 低：ユーザーがデータ領域を誤操作可能 |
| 6 | DBリンク | `rich.zaikor@ricdb` 等のリモートDBリンク使用 | 低：ネットワーク障害時にタイムアウト |
| 7 | 古いデータ削除 | 50,000件超で3年以前を自動削除（ユーザー確認なし） | 低：意図しないデータ消失 |
