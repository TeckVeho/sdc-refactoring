# EXメニュー仕様書 共通ルール

> 本文書は `docs/` 配下の全仕様書に適用される共通ルールを定義する。
> 各仕様書の業務仕様・解析結果は変更せず、構成・表記・記載範囲の統一を目的とする。

---

## 1. タイトルと冒頭メタ情報

### タイトル

```
# {ファイル名（拡張子なし）} 仕様書
```

- `.xlsm` `.xltm` 等の拡張子はタイトルに含めない
- 例: `# Ex生産情報一覧1 仕様書`

### 冒頭メタ情報（必須）

タイトル直下に blockquote で以下を記載:

```markdown
> **ファイル種別**: .xlsm（マクロ付き）
> **用途**: （1〜2文で業務目的を説明）
> **VBA プロジェクト**: モジュール N 本（.bas X / .cls Y / .frm Z）
> **外部連携**: DSN=ricdb（Oracle）等
> **解析日**: YYYY-MM-DD
```

---

## 2. 凡例（表記ルール）

冒頭メタ情報の直後に `## 凡例（本仕様書の表記ルール）` を設置する。

### 必須表記ルール

| 種別 | 表記 | 例 |
|---|---|---|
| モジュール（.bas / .cls） | **太字** | **スタート処理.bas** |
| ユーザーフォーム（.frm） | **太字** | **SoutiSenntaku.frm** |
| プロシージャ / イベント | \`コード体()\` | `生産情報開始処理()` |
| シート名 | 「」 | 「未処理品一覧」 |
| セル参照 | \`コード体\` | `$W$3` |
| 名前付き範囲 | \`コード体\` | `Amari` |
| DB テーブル / カラム | \`コード体\` | `ExKeikakuX` / `kakunin` |
| ユーザー操作 | （操作名） | （処理方法実行 Click） |
| 主要マーク | ✓ | ✓ = 保守時に最初に確認すべき項目 |

### セル内改行の表記

セル値にリテラル改行（`CHAR(10)`）を含む場合:

- ✗ `"会社\nｺｰﾄﾞ"` — エスケープシーケンスに見え、文字化けと誤認される
- ✓ `"会社（改行）ｺｰﾄﾞ"` — 日本語で明示

### 推定・不明事項の表記

- ソースから論理的に導ける情報 → そのまま記載
- ソースから根拠を確認できない意味付け → `（推定）` を付与
- 確認不能 → `（不明）` を付与

## 3. ✓（主要マーク）の判定基準

全仕様書で以下の基準を統一する:

| 章 | 対象 | ✓ の判定基準 |
|---|---|---|
| 1.1 | シート | ユーザーが直接操作する、または VBA が動的に表示/非表示を切り替える |
| 1.2 | ユーザーフォーム | ユーザー入力を受け付ける、または業務フローの起点となる |
| 1.3 / 6.0 | VBA モジュール | ① ユーザー操作の起点 ② DB I/O を含む ③ 他モジュールから呼ばれる Public ④ コード行数上位 25% のいずれか |
| 2 | セル / 名前付き範囲 | VBA から `Range()` で代入または参照され、業務ロジックに直結する |
| 5 | ボタン / コントロール | DB 更新・画面遷移・計算実行など副作用のある操作を起動する |
| 8.2 | DB テーブル | INSERT / UPDATE / DELETE の対象（参照のみは ✓ なし） |

## 5. 各章の記載ルール

### §2 シート詳細

- **§2.0 シート可視性一覧**: 全シートの visible/hidden/xlVeryHidden を記載。VBA による動的制御がある場合は「表示するタイミング」「非表示にするタイミング」「制御プロシージャ」列を設ける
- **ブック設定**: `showSheetTabs="0"` 等のブックレベル設定があれば §2.0 冒頭に記載
- **非表示行・列**: 各シートに「非表示行・列」サブセクションを設け、非表示の行範囲・列を明記。なければ「なし」と記載
- **シートの目的**: 各シートセクションの冒頭に1〜2文で目的を記載

### §3 名前付き範囲一覧

- テーブル列: `| ✓ | 名前 | 参照先 | 用途 | VBA参照元 |`

### §3.1 データの入力規則（必須）

Excel のデータの入力規則（`<dataValidation>`）を検出し、以下の表で記載:

```
| セル | 名前付き範囲 | 種別 | 制約 | 用途 |
```

- 種別: 整数 / 小数 / リスト / 日付 / テキスト長 等
- 制約: 数値範囲（例 `0.1〜99`）、リスト参照元、演算子（`>`, `>=` 等）
- 該当なしの場合は「検出された入力規則なし」と明記

### §5 ボタン・マクロ対応

- **Form Control**（vmlDrawing の `<x:FmlaMacro>`）と**描画図形**（drawing XML の `macro="..."` ）の両方を記載
- 「ボタンなし」と判定する前に、drawing XML の図形マクロも確認すること
- **ショートカットキー**: VBA の `Attribute xxx.VB_Invoke_Func` から検出し、専用セクション（§5.x）に記載

### §8 DB 接続・外部連携

- **§8.2 テーブル一覧**: 「キー列」の定義を冒頭に注記する（= JOIN 条件または UPDATE/DELETE の WHERE で使用される列）
- **§8.3 SQL 文一覧**: SELECT には必ず WHERE 条件を記載する。動的生成の場合は条件パターンを表で示す。`...` による省略は禁止

## 6. データフロー場所マーク（§9）

| アイコン | 種別 | 意味 |
|---|---|---|
| 📊 | シート操作 | ワークシート上のセル書込み・読取り・表示変更 |
| 🖥️ | 画面操作 | ユーザーフォーム（.frm）の表示・入力・操作 |
| 🗄️ | DB操作 | Oracle / Access DB への SELECT / INSERT / UPDATE / DELETE |
| 📄 | VBA内部処理 | 変数計算・条件分岐など、画面・シートに直接関与しない処理 |

## 7. フォント・表示方針（No.1 対応）

### 問題

一部環境で Gungsuh（韓国語フォント）がフォールバック選択され、`\` が `₩` に表示される。

### 原因

仕様書に半角カタカナ（U+FF65〜FF9F）が多数含まれ、レンダリング時にフォントフォールバックが発生する。

### 対策

Markdown をレンダリング（PDF/HTML/Word 変換）する際、以下のフォントを優先指定する:

```css
body {
  font-family: "BIZ UDPGothic", "Yu Gothic", "Hiragino Sans", "Noto Sans JP", sans-serif;
}
code, pre {
  font-family: "BIZ UD Gothic", "Source Han Code JP", "Noto Sans Mono CJK JP", monospace;
}
```

### ソースファイル側の方針

- 半角カタカナは Excel VBA のシート名・変数名から転記されたものであり、ソース上の正しい表記。変更しない
- UNC パスの `\\` はバックスラッシュとして正常に記載されている
- ₩（U+20A9）はソースに含まれていない（レンダリング側の問題）
